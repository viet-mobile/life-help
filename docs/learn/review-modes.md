# 복습 모드 (Review modes)

**이 릴리스(Korean RC)에서는 한국어 사이트(study.korean)에만 켜져 있다.** Math·English 사이트는 기존 화면·API 그대로다: `/modes`·`/cards`는 그 사이트에서 404, `cards`·`reveal` API는 404, `mode` 파라미터는 무시된다. 아래 표의 영어 `dict`/`listen` 형식은 영어 릴리스 트레인(별도)에 속하며 이 후보에는 영어 데이터가 없다.

구현됨(브랜치 `claude/sleepy-ride-4x56y2`) / 아직 아님을 구분해 적는다. 모든 번역은 AI 번역이며 원어민·교사 검토가 아니다.

## 구현된 것
| 모드 | 어떻게 고르나 | 영어 은행 | 한국어 은행 |
|---|---|---|---|
| 보기에서 고르기 `choice` | 4지선다/참거짓, 소리 없이 풀림 (낱말·문장이 글자로 보임) | 있음 | 있음 |
| 듣고 고르기 `listening` | `audioText` 있고 글자 `target` 없음 | `listen`(검토된 문장에서 파생) + 기존 | `listen` 등 |
| 순서 맞추기 `order` | `ordering` | `order` | `order` |
| 받아쓰기 `dictation` | `short_answer` + `dictation` 키 + `audioText` | `dict`(검토된 문장에서 파생) | `dict` 코드 완료, **번역 템플릿이 올 때까지 비활성**(아래) |
| 카드 넘기기 | 서버는 앞면만, 뒷면은 `reveal`로 | `enko` 형식 | `meaning` 형식 |

- 세션: `POST /api/learn/start { kind:"practice"|"review", mode }`. 모드가 없으면 기존 동작. 모드만 있고 스킬이 없으면 학습자가 이미 도달한(잠기지 않은) 레슨의 스킬에서만 뽑는다. 알 수 없는 모드 값은 무시된다.
- 모드 분류(`lib/learn/reviewModes.ts#questionMode`)는 문제가 *무엇을 요구하는가*로 정한다. 글자와 스피커 버튼이 같이 있는 문제는 듣기가 아니라 고르기.
- 허브: `/study/<site>/modes`, 카드: `/study/<site>/cards`. 대시보드에 링크.
- 진행·보상: 모드 세션은 일반 연습 세션과 같은 `submitAttempt` 경로를 쓴다. 따라서 진행, 숙련도, SRS, 오답·힌트·재시도 보상 규칙이 모드와 무관하게 같다(오답·힌트·재시도의 보상 규칙은 기존 엔진 동작 그대로이며, 모드별로 따로 재검증하지는 않았다). **카드는 서버에 아무것도 기록하지 않고 XP·코인·숙련도·복습 일정에 영향이 없다.** ‘알았어요/다시’ 표시는 이 브라우저(localStorage)에만 있다.
- 대상 언어/학습자 언어 분리: 카드 앞면=목표어 낱말(영어 낱말, 한국어 낱말), 뒷면=학습자 언어 뜻. 한쪽에 두 언어를 섞지 않는다.
- 키보드: 카드는 Space/Enter(뒷면), 1(다시), 2(알았어요). 소리 없는 환경: 허브가 소리가 필요한 모드를 표시하고 ‘고르기/순서 맞추기’를 안내한다.

## 받아쓰기 정규화 규칙 (`normalizeDictation`)
- 영어: 대소문자 무시, 앞뒤·중복 공백 무시, 문장부호 무시, 곧은/굽은 따옴표·대시 동일 취급.
- **봐주지 않는 것**: 철자 오류, 아포스트로피·하이픈 유무가 낱말 정체를 바꾸는 경우, 낱말 누락/추가.
- 한국어: 앞뒤 공백과 문장부호만 무시. **띄어쓰기와 철자는 봐주지 않는다**(자동으로 맞는 것으로 바꾸지 않는다).
- 정답 후보는 문항이 가진 `accepted` 목록이며 동의 표현을 추측으로 받아 주지 않는다.
- 한계: 소리는 기기 음성(TTS)이라 같은 문장이 기기마다 다르게 읽힌다. `audioText`가 브라우저로 전달되므로 받아쓰기 문장은 네트워크 응답에서 보인다(브라우저 TTS의 구조적 한계; 문항 은행의 보호 대상은 정답 키·힌트·해설이다).

## 어순 배열의 동등한 정답 기준
- 정답은 문항의 키 순서 하나 + 같은 글자의 타일끼리의 교환(`I … I`)만 인정한다.
- 자연스러운 다른 어순이 있는 문장(부사 위치 등)은 `ord:false`로 출제하지 않거나 키를 늘려야 한다. 영어 은행의 순서 문제는 짧은 문장(3~12 낱말)에서만 만든다. 검토 중 ‘다른 어순도 자연스럽다’고 지적된 항목을 일부 고치거나 뺐지만, 전체 순서 문항을 이 기준으로 전수 점검하지는 않았다(미완료 항목으로 남김).

## 한국어 `dict` 형식 (비활성 이유)
`KForm "dict"`와 문항 생성 코드는 들어 있다. 템플릿(지시문·힌트·해설)은 언어별로 필요하고, 14개 전체 언어에 빠짐없이 있어야 그 언어에 한국어 은행이 열린다. 템플릿이 없으면 `expandKoreanBank`는 이 형식을 만들지 않는다(조용한 대체 없음). 템플릿을 영어 키트에 넣고 46개 언어 번역을 병합할 때 함께 켠다.

## hoc-tieng-viet-mobile 검토 결과
공개 저장소(HEAD 8101f91)의 `app_logic.js`는 TTS 목소리 선택(voiceURI 키, `voiceschanged`, iOS 예외)과 5가지 복습 모드를 가진다. **저장소에 LICENSE 파일이 없어 코드를 복사하지 않았고**, 같은 동작을 이 코드베이스의 구조(서버 판정, 정규화 함수, 설정 저장소)에 맞춰 독립 구현했다. 아이디어(모드 구성)는 공개 사실이며 표현은 복제하지 않았다.

## 아직 안 한 것 / 검증 필요
- 한국어 `dict` 번역 템플릿, 모드 UI 문구 46개 언어 번역(키: `modes.*`, `cards.*`) — 번역 전에는 `ko` 문구로 대체되므로 **다른 언어 노출 전에 번역 병합 필요**.
- RTL(아랍어 등) 및 실제 모바일 화면 확인은 코드 레벨(논리 속성/키보드 핸들러)만 점검했고 기기 검증은 아직.
- 카드의 SRS는 기기 로컬 Leitner 상자 하나뿐이며 서버 SRS와 연동하지 않는다(의도).
