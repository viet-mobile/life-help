# 통합 · 다국어 · 배포 상태 (2026-10-17)

## 문항 규모 (과목별 10의 배수, 하위 분야 균형)
- 수학 210 · 영어 140 · 한국어 120 = 470 (시범 36 포함). 균형 통계는 `BATCH2.md`.
- 과제는 모두 AI가 작성했고 **교사·원어민의 독립 검토는 받지 않았다.** 학생·교사 검토 의견(품질 양호)은 사용자가 전한 것이며, 이 저장소에서 확인한 기록은 없다.

## 기존 학습 체계에 통합한 방식
- 학습 사이트(`/study/[site]/…`)의 PlayShell 안에 `think` 화면(`app/study/[site]/(play)/think/page.tsx`)과 대시보드 카드(think-card)를 추가했다. 별도 사이트·DB·스키마 변경 없음.
- 허브(`components/think/ThinkHub.tsx`)는 학생의 학년·사이트(수학/영어/한국어)로 목록을 걸러 준다. 진행 상태는 **기기 로컬 저장**이다(서버 저장 없음).
- `tests/learn/supabase-isolation.test.ts`의 허용 접두사에 `lib/think/`, `components/think/`를 추가했다(둘 다 자격 증명·Supabase를 쓰지 않는 순수 클라이언트 코드와 JSON).

## 지시문 번역 (en, zh-Hans, zh-Hant, ja, vi)
- 대상: 수학 전부, 영어 전부, 한국어 전부(영어 번역은 한국어 과목 제외 — 한국어 과목은 한국어 학습이 목적).
- 방식: 과제를 평탄화(`lib/think/flat.ts`)한 문자열 목록을 번역해 `lib/think/i18n/<lang>/<파일키>.json`(`{과제id:{경로:번역}}`) 오버레이로 저장하고, 화면 언어에 맞춰 지연 로딩한다(`lib/think/localize.ts`). 번역이 없으면 원문(한국어)으로 돌아간다.
- 번체(zh-Hant)는 간체를 OpenCC `s2twp`로 변환한 것이다(`scripts/think/tr-hant.py`).
- 번역 파이프라인: `tr-prepare.ts`(청크 생성) → 언어별 번역 → `tr-merge.ts`(병합·검증) → `tr-hant.py` → `gen-extra-index.mjs`.
- 검증: `tests/think/i18n.test.ts` — 모든 번역 대상 문자열 존재, 빈 문자열 없음, 구조(문자열 수) 보존, 통화 단위를 제외한 한글 잔존 상한.

### 알려진 한계 (정직하게)
- **AI 번역이며 원어민 검토를 받지 않았다.** 번체는 자동 변환이다.
- 수학은 서술형 답을 학습자 언어로 쓰므로 **한국어 이외 UI에서는 서술 답의 표면 검사를 끈다**(`checksOffFor`). 선택·구성 단계의 채점은 그대로 동작한다.
- 통화 단위 `원`/`만 원`, 가·나 같은 항목 이름, 지문 속 인용문은 언어별로 처리 방식이 조금 다르다(언어별 번역가 판단). 일본어 번역은 한국어 수사를 숫자로 풀어 쓴 곳이 많아 숫자 일치 검사 경고가 많다(대부분 정상).
- 한국어 과목의 영어 작문 모범 답안은 zh-Hans에서만 중국어로 번역되고 ja·vi에서는 영어 그대로다(언어 간 불일치). 검토 시 확인 필요.
