# 시범 과제 작성 규칙 (36개 = 수학 12 + 영어 12 + 한국어 12)

타입: `lib/think/types.ts`. 검증기: `lib/think/validate.ts` (`npx vitest run tests/think`). 예시: `lib/think/data/example-math.json`.
식 언어(만들기 단계의 제약): `lib/think/expr.ts` — 숫자, 변수, + - * / % ^, 비교, && || !, abs min max floor ceil round gcd lcm sqrt isPrime digitsum.

## 단계 종류
- `choose`: 단일/복수 선택. 선택지마다 `reveals`(그 선택이 보여 주는 생각)를 쓴다(정답 제외). 여러 해석이 가능하면 `acceptable`.
- `pickLine`: 풀이/메시지/논증의 줄을 보여 주고 틀린 줄을 고른다(`wrong`).
- `write`: 서술. `checks`는 표면 특징(정규식)만, `selfAssess`는 학생이 모범 답안을 읽고 스스로 점검, `modelAnswers` ≥ 2(서로 다른 좋은 답), `badAnswers` ≥ 1, `humanReview`는 사람이 봐야 할 부분. 모든 모범 답안은 자기 `checks`를 모두 통과해야 하고, 나쁜 답은 하나 이상 실패해야 한다(시험이 검사).
- `build`: 수치 예(반례, 여러 해법, 만든 문제의 조건)를 학생이 입력. `vars`, `constraints`(식), `need`(필요한 서로 다른 예 수), `modelRows`(조건을 만족하는 예 ≥ need, 서로 달라야 함), `badRows`(조건을 어기는 예). 선택적 `because`(서술 단계).
- `reveal`: 자료를 단계적으로 공개하며 매 단계 예측을 고르게 하고 이어서 수정하게 한다(≥ 3단계, 단계마다 `reasonable` 여러 개 가능).

## 원칙 (위반하면 반려)
1. 학생이 추론/비교·평가/오류 수정/반례·성립 조건/정보 충분성 판단/제약 속 다중 해법/판단 수정 중 하나 이상을 실제로 수행해야 한다. 지문 길이·낯선 어휘·숫자 치환·보기 순서는 사고력이 아니다.
2. 보기 단서나 문장 길이로 정답이 드러나면 안 된다. 정답이 여러 개일 수 있으면 하나만 인정하지 말고 `acceptable`/`alternatives`에 쓴다.
3. 힌트는 정답이 아니라 다음 행동(관찰·비교·검증)을 안내한다. 단계마다 ≥ 2개, 점점 구체적으로.
4. `curriculum`은 근거(성취기준 코드/문서)가 있을 때만, 없으면 null. 과제 하나로 성취기준 전체를 충족한다고 쓰지 마라.
5. `uiLang`: 수학·영어(과목 사이트의 지시문)는 `ko`. 한국어 과목은 학습자 언어(`en`)로 지시문·힌트·해설·의미를 묻는 보기를 쓰고, 학습 대상 한국어(대화·공지·메시지)는 그대로 둔다.
6. 한국어/영어 `write` 정규식은 비영어/비한국어 입력에 흔한 변형(띄어쓰기, 어미)을 고려해 느슨하게, 그러나 성의 없는 답이 통과하지 않게.
7. 수학 `build`의 제약은 학생이 만든 예가 맞는지 자동으로 가릴 수 있는 것만. 서술 품질은 `write`의 자기 점검으로 남긴다.
8. 개인정보·특정 실제 인물·종교/정치 편향·성별 고정관념을 쓰지 마라. 문화 의존 소재는 `cautions.culture`에 밝혀라.
9. 한국어 `choose`/`pickLine`의 한국어 지문에서 정답 단서가 어휘 난이도(어려운 낱말 = 오답 등)로 드러나지 않게 하라.

## 분포
- 과목별 12개: 수준 1/2/3 각 4개(수학·영어 = 초등/중등/고등, 한국어 = 초급/중급/고급).
- `generative: true` 과제 ≥ 4개(학생이 답·표현·모델·문제를 직접 생성).
- 형식(`format`)은 과목별로 여러 종류를 쓰고, 7개 형식을 전체에서 모두 사용한다.
- 예상 시간 `minutes` 3~30, 선수학습 `prerequisites` 명시.

## 추가 배치(학년/등급/선택과목별 10개) 작성 규칙
- 파일: `lib/think/data/extra/<subject>-<grade>.json` (JSON 배열, 정확히 10개). id: `x-<subject 첫 글자 m/e/k>-<grade 소문자>-01..10` (예 `x-m-e3-01`, 선택과목 `x-m-el-econ-01`). 각 과제에 `grade`, `topic`(그 학년의 하위 분야) 필수. `level`은 초등/초급=1, 중등/중급=2, 고등/고급=3 (K1-3=1, K4-6=2, K7-10=3). `status`는 쓰지 마라(코드가 draft로 표시).
- 10개는 그 학년의 하위 분야에 고르게 나눠라(수학: 수와 연산/도형·기하/측정/규칙성·함수·대수/자료와 가능성 중 학년에 맞는 것, 영어·한국어: 읽기·대화·안내문/메시지·쓰기 등). 학년 수준을 넘는 선수학습을 요구하지 마라.
- 형식 7종을 한 파일 안에서 가능한 한 고르게 쓰고, 생성형(`generative:true`) ≥ 4개, 단계 종류(choose/pickLine/write/build/reveal) ≥ 3종. 한 과제는 2~4단계, 서술(write) 단계는 과제당 최대 2개로 **간결하게** 쓴다.
- 첫 36개 과제의 독립 검토에서 나온 결함을 반복하지 마라:
  1. 정답 선택지가 가장 길거나 유일하게 신중한 표현이면 안 된다(길이·어조를 맞춰라). 같은 과제 안에서 정답 위치(A/B/C…)를 단계마다 바꿔라. 소거법으로 풀리는 우스꽝스러운 오답 금지.
  2. 모든 선택지에 `reveals`(정답 포함: 그 선택이 보여 주는 생각, 정답을 직접 말하지 않기). 복수 선택에서 빠뜨린 정답에도 쓸모 있는 진단이 되게.
  3. 정규식: 단어 경계·부정문을 고려. "불가능"이 "가능"에, "비싸"가 "싸"에, "example"이 "exam"에, "바뀌지"가 "바뀌"에 걸리지 않게. 각 write 단계마다 타당한 서로 다른 표현 2개 이상이 통과하고 부적절한 답 2개 이상이 실패하는지 직접 확인(모범 답안 ≥ 2, 나쁜 답 ≥ 1은 검증기가 강제).
  4. pickLine의 설명 글에서 줄 번호는 **1부터**(화면이 1부터 표시). 선수학습·제목·힌트가 정답 연산/답을 말하면 안 된다.
  5. `build`는 순열 등 같은 예를 중복 인정하지 않게 `distinctBy`를 순열 불변 식으로. modelRows는 서로 달라야 한다.
  6. 일정·시간 모순 등 전제는 객관적으로(명시적 시각). 한국어는 자연스러움 확인.
  7. 힌트는 다음 행동만. 예상 시간 현실적으로.
- 작성 후 `cd /home/user/think-wt && node scripts/think/gen-extra-index.mjs && npx vitest run tests/think` 가 통과해야 한다(다른 저자의 파일이 동시에 추가될 수 있으므로 실패하면 **자기 파일 때문인지** 확인: 임시 테스트로 `validateSet`을 자기 파일에만 적용). 인덱스 파일은 마지막에 한 번만 다시 생성하고 직접 편집하지 마라.
